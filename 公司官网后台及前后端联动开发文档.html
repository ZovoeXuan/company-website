1. 项目目标与范围

1.1 最终应交付的结果

交付一个可公开访问的公司官网，以及供公司内部人员登录的内容管理后台。运营人员可以不修改代码完成：更换首屏图、调整文案和导航、维护产品及方案、发布案例和新闻、调整首页推荐、更换联系信息，以及查看处理访客咨询。

完整链路必须成立：后台录入 → 保存草稿 → 登录预览 → 管理员发布 → 官网从公开接口读取发布版 → 访客浏览/咨询 → 管理员处理咨询。只做静态官网，或后台保存后官网仍使用写死的数据，都不算完成。

1.2 首版假设

• 一个公司、一个中文站点、两个内部角色；官网访客不需要注册或登录。

• 官网和管理后台均使用 Vue，分别构建；Java 单体应用提供两组 API，MySQL 存业务数据。

• 页面模板、模块顺序、布局、颜色和响应式行为由前端代码固定；运营在后台维护模块内容和开关。

• 桌面和移动端共用同一份业务数据；首屏图片允许分别上传两种尺寸。

• 详情 URL 使用稳定 ID，例如 /products/101，首版不实现可编辑 slug。

• 不接入公司的订单、物流、财务等业务系统。参考站涉及的业务产品在本项目中只是展示内容。

菜单和按钮按权限显示，服务端对每个操作再次校验。直接调用接口也必须得到相同限制。访客只允许读公开内容、提交咨询，不得读后台配置或咨询记录。

4.2 登录规则

• 账号 4～50 个英文字符、数字、下划线、连字符；数据库唯一；登录前后去除账号首尾空格，密码不得自动去空格。

• 密码建议至少 12 位，允许较长口令，最长 128 字符。使用 Spring Security PasswordEncoder 的单向哈希；不保存明文或可逆密码。

• 登录失败统一提示“账号或密码错误”；按账号/IP 组合限制尝试次数，例如 5 分钟内失败 5 次后暂缓 10 分钟，参数可配置。

• 登录成功轮换会话 ID；30 分钟无操作失效。生产 Cookie 设置 HttpOnly、Secure、SameSite=Lax。

• 退出、禁用账号、重置密码后撤销该用户所有相关会话；修改本人密码后也要求重新登录。

• 不开放自助注册和找回密码。管理员可重置编辑账号；初始管理员通过部署时一次性初始化创建，无固定生产默认密码。

• 禁止禁用或降级最后一个启用的管理员；并发操作时需要数据库事务锁住管理员集合进行检查。

4.3 所有管理列表与表单的共同行为

列表有关键字、发布状态、是否有未发布修改、分类、时间筛选及分页；显示标题、封面、类型、线上状态、草稿版本、发布版本、最后修改时间和操作。

编辑页显示“保存草稿”“预览”“发布”及当前版本。编辑角色不显示发布按钮。发布前列出缺失字段和引用问题；成功提示版本与官网查看入口。未保存离开时提醒，保存失败保留输入；提交中禁用重复点击。

删除、下线、禁用账号必须二次确认，提示具体对象和影响位置。批量发布、批量删除不进入首版。图片和关联内容选择器必须可搜索，并显示资源状态，不能要求运营自己查 ID 后输入。

5. 草稿、发布、下线与预览：核心规则

5.1 状态模型

官网状态使用 UNPUBLISHED（未发布）、PUBLISHED（已发布）、OFFLINE（已下线）。另外维护 draftVersion、publishedVersion、lockVersion。已发布内容可以同时有未发布修改，后台显示两个标记，例如“已发布 / 有未发布修改”。

hasUnpublishedChanges = publishedVersion 为空，或 draftVersion != publishedVersion。不要用“保存草稿”把一条已发布内容的线上状态改成未发布。

操作草稿线上快照官网结果
新建并保存新增、版本为 1空列表无记录，详情 404
已发布内容保存修改更新，草稿版本加 1保持原样保持原发布内容
发布当前草稿不改变已保存草稿含义完整替换，记录版本/发布人新请求使用新发布内容
下线保留保留供追溯，状态 OFFLINE从公开列表和推荐移除，详情 404
重新发布发布当前保存的草稿生成当前快照重新公开；有修改时清楚提示本次发布哪一版
删除逻辑删除不再公开只允许未发布/已下线且无引用的内容

配置 SITE、NAVIGATION、HOME、ABOUT、CONTACT、PRIVACY 是固定单例，不允许新增未知键或删除；通过发布其中模块开关控制显示。SITE、HOME、CONTACT、PRIVACY 等基础配置不提供整体下线按钮。

5.2 保存与发布的校验强度

保存草稿允许尚未填完标题、摘要等业务字段，但必须校验 JSON 类型、文本最大长度、数组上限、资源存在性、安全链接、富文本安全和权限。发布时再完整校验必填项、当前资源可用性、分类类型及关联对象是否已发布。接口返回所有已发现字段错误，避免运营一次只能修改一个问题。

发布提交 expectedLockVersion 和 expectedDraftVersion。保存、发布、下线、删除均必须使用数据库条件更新或行锁保证原子比较；不能先查询版本再无条件写入。版本不匹配返回 409，提示刷新后重新核对。

发布事务按顺序完成：读取来源与关联候选集合 → 按第 8.4 节统一锁顺序锁定来源及目标 → 重读并核对版本和角色 → 按固定 DTO 校验并清洗 → 校验引用 → 将 draft_json 复制为 published_json → 提取发布查询字段 → 更新发布引用 → 设置发布版本、状态、时间和操作人 → 写成功审计 → 提交。任一步失败全部回滚。

首版只有单个配置/内容的发布事务，没有“整个官网一键原子发布”。上线顺序为：素材 → 分类 → 产品/方案/案例/新闻/客户标识 → 站点及单页 → 导航与首页。跨对象更新期间由公开接口过滤失效关联。

5.3 下线、引用与删除

内容被首页、导航、其他内容关联时允许下线，操作前展示影响；公开接口读取时自动剔除无效关联，不能输出可点击的死链接。父导航过滤后无子项且无有效目标时隐藏。首页模块过滤后无数据则整块隐藏。

删除仍有 DRAFT/PUBLISHED 引用的内容或图片必须返回 409，并列出“首页/案例推荐”等位置。先解除引用，再删除。下线的来源对象保留快照，引用也保留用于追溯和删除检查；公开媒体是否可读还需核对来源当前是否有效。

分类如仍有已发布内容使用，禁止下线或删除；若只有草稿引用，允许下线但禁止删除，并提示相关草稿发布前需要重新选择分类。

5.4 预览与生效时间

预览使用后台登录会话和 /api/admin/preview/*，页面标明“草稿预览”。不得通过给公开 URL 增加 preview=true 返回草稿，不提供免登录预览链接。首版预览本对象的草稿，关联对象使用各自最新发布版，并在预览页说明此规则。

公开 JSON API 使用 Cache-Control: no-store；官网不长期写入 localStorage，不在 Service Worker 缓存 CMS 响应。发布或下线成功后，重新加载官网应在 5 秒内看到变化；已经打开的页面以刷新更新，不实现主动推送。数据库中的新闻展示日期不承担定时发布功能。

6.13 素材管理

首版接收 JPG/JPEG、PNG、WebP，单张最多 5MB、最大 2000 万像素。通过后缀、实际类型和图像解码共同校验；SVG、HTML、脚本、可执行文件、视频和任意附件在首版拒绝。

上传成功返回 mediaId、宽高、体积、原文件名和后台预览地址。磁盘文件名使用服务端随机存储键，不采用原文件名；不接受客户端传磁盘路径。不覆盖旧文件，替换图片必须上传新资源并发布新引用。

列表支持文件名搜索、上传时间、是否被引用筛选，可查看引用位置。存在草稿或发布引用时禁止删除；删除只标记逻辑删除，文件物理清理由运维后续执行，不提供一键彻底清理。

素材目录不直接映射为公开静态目录。后台图片预览走鉴权接口；公开 /api/public/media/{id} 只有图片存在至少一个当前有效发布来源引用时才返回文件，否则 404。来源下线、删除或无效分类必须参与有效性检查。首版图片响应同样 no-store；以后采用缓存时须明确撤回行为。曾公开过的图片无法保证从第三方缓存中撤回。

富文本图片只允许从素材库选择。数据库中的规范化 bodyHtml 对 img 只保存受控 data-media-id、alt 等白名单属性，移除客户端 src；保存/发布时扫描媒体 ID 并维护引用。返回 admin/preview/public DTO 时，服务端再按上下文注入对应 src，不能把后台鉴权图片地址固定保存进发布正文。清洗器须保留经过验证的 data-media-id。拒绝外部图片 src、粘贴 base64 图片、任意 iframe。普通正文外链可使用合法 http/https。不能只处理封面图片而漏记正文中的素材引用。

7.1 官网表单

companyName是1～100 字
demand是1～2000 字，普通文本
sourcePath是本站相对路径，最长 200；只保留 path，不存 URL query 中潜在个人信息
sourcePosition是HOME_HERO/HOME_BOTTOM/PRODUCT_DETAIL/SOLUTION_DETAIL/CASE_DETAIL/CONTACT/FLOATING/NAVIGATION/FOOTER/OTHER_CTA 白名单；导航、页脚和其他合法咨询动作分别映射对应值

7.2 提交流程与幂等

1. 打开表单时获取发布的 formEnabled 与隐私版本，用户查看说明并主动同意。

2. 前端校验；提交中按钮禁用。后端先校验请求结构、长度与 key 格式，规范化载荷并计算 payload_hash；此阶段不校验关联当前状态或当前隐私版本。

3. 查询 key：已经成功且 hash 相同则直接返回原成功结果；hash 不同返回 409。旧成功重试不再受后来表单关闭、隐私升级、关联下线影响，也不重复消耗业务提交额度，但仍受通用请求频率限制。

4. 未命中 key 时才校验当前表单开关、字段业务规则、当前同意版本、有效关联和业务提交限流；通过后将 key/hash 与线索一起入库，唯一约束防并发重复。

5. 并发插入发生唯一键冲突时回读已提交记录，同 hash 返回原受理结果，不同 hash 返回 409；不得仅依靠预先查询。失败未落库的请求没有成功幂等记录，重试仍按当前业务状态校验。

6. 成功只返回 accepted=true 与随机 receiptNo，不回显手机号或提供查询其他线索的接口。成功后清空表单、重新生成下一次 key；网络超时保留输入及原 key，不能展示虚假的成功提示。

首版不接短信服务。对新提交配置 IP 与手机号摘要限流，例如同 IP 每分钟最多 3 次、同手机号 10 分钟最多 3 次；这些是可配置初值，须结合公司网络情况调整。429 返回可理解提示与 Retry-After。蜜罐/验证码可作为二期增强，不在无服务商凭证时伪造短信验证成功。

7.3 后台处理

管理员列表支持状态、日期、公司/姓名关键字筛选，显示姓名、公司、脱敏手机、来源、关联内容、提交时间、状态。点击详情并审计后可查看完整手机；编辑角色没有任何读取权限。

状态为 NEW → CONTACTED → CLOSED，也可 NEW/CONTACTED → INVALID。CLOSED/INVALID 若需重新跟进，管理员必须填写原因后可回到 CONTACTED；每次操作记录日志。首版保存 last_note（最多 2000）、处理人、处理时间，日志记录状态变化和有无备注，不复制敏感备注全文。

首版不做线索删除按钮、Excel 导出、邮件/短信通知或 CRM 对接。保留周期由公司负责人在上线清单中确认，写入运维手册；正式上线前落实受控的到期清理方式及备份保留策略，测试数据先清理。保留周期不是由实习生自行决定的业务规则。

7.4 敏感字段存储约定

手机号使用服务端维护的密钥进行认证加密保存，密文内包含算法版本、随机 nonce 和校验 tag；密钥不进数据库、不进源码。可使用成熟库/平台密钥能力，禁止自行设计加密算法。列表用末四位脱敏，限流可用带服务端密钥的规范化手机号 HMAC 摘要；不保存可被直接枚举的普通手机号哈希。

IP 只用于防滥用，日志不要长期保存原始地址；限流键使用受控摘要并设置短期失效。名单详情授权、备份访问、密钥备份同样需要受控。姓名、公司和需求也不输出到普通访问日志。

8.3 内容已发布查询投影

cms_content 另含 content_type，创建后不可更改。为了公开列表筛选、搜索、排序，增加 published_title、published_category_id、published_sort_order、published_display_time。分类另有对应的已发布名称、排序投影。具体类型见 schema.sql。

这些投影只能从本次发布 DTO 提取，并在同一发布事务中更新；草稿保存不得写入。否则虽然正文还没发布，官网搜索和分类已按草稿变化，仍然属于发布隔离错误。

后台搜索可用 draft_json 中的 title；公开搜索只查 published_title。公开查询通用条件为：

deleted = 0
AND publication_status = 'PUBLISHED'
AND published_json IS NOT NULL

有分类的内容还需核对已发布分类存在、类型正确且有效。新闻按 published_display_time DESC, id DESC；其他内容按 published_sort_order ASC, id DESC。首页手选 ID 列表须按配置数组重新组装，不能依赖 SQL IN 的返回顺序。

索引围绕内容类型、发布状态、删除标记、已发布分类和排序时间建立。新闻 title 的小数据量关键字查询可用参数化 LIKE；不为首版引入搜索引擎。外键与应用层类型约束的实际分工见脚本说明，不能把 JSON 中存在一个 ID 当成关系已校验。

8.4 引用维护和并发约束

保存时重新扫描 DTO 的素材/内容/分类关联；更新 DRAFT 引用。发布时重新计算并替换 PUBLISHED 引用；引用的字段路径记录为 HOME.services.groups[0].contentIds[1] 等，便于后台定位。前端不得直接增删引用表。

正文图片同样扫描；内部正文内容跳转优先使用结构化关联区，首版正文中的自由链接仅允许外链，避免漏记站内内容引用。分类引用通过 content 草稿 DTO 与 published_category_id 校验和查询，不必再伪装成 content_ref。

逻辑删除后清除该来源的引用；删除前先检查其他来源是否引用它。引用唯一约束按来源、阶段、目标和字段位置定义，避免重复插入。资源/目标校验与保存、发布、删除并发时，先读候选引用集合，将来源对象也加入集合，按固定表顺序、ID 升序统一加锁，再重读来源版本与引用集合。若候选集合已经变化，回滚并返回版本冲突，不能在持有来源锁后随意逆序补锁。这样可防止刚校验通过目标就被删除；仍须捕获数据库死锁/锁等待超时，完整回滚后返回 409 RETRYABLE_CONFLICT，提示刷新后重试，不能返回成功或丢失草稿。单实例不等于可以忽略并发请求。

8.5 建表与迁移要求

附带 schema.sql 提供基线；开发时纳入版本迁移，后续改结构新增迁移，不能修改已经在共享环境执行的旧迁移。Spring Session 表从实际依赖携带的 MySQL 脚本初始化，避免手写与框架版本不一致的表。

脚本不创建带默认密码的生产账号，不包含正式公司内容，不擅自创建或删除数据库。空配置草稿初始不可公开；应用需展示合理初始化提示，正式验收再检查基础配置全部发布。开发者必须在空测试库实际执行迁移和基本读写后提交结果；本文交付的是开发规格及脚本基线，不代表应用已经实现或数据库已执行验证。

9.2 分页、查询和排序

参数 page 从 1 开始，pageSize 公开默认 12、后台默认 20，最大均为 50；非法值返回 400。统一分页 data：{items:[],page:1,pageSize:12,total:0}。超出末页返回空 items，前端提供回第一页入口。

关键字最多 50 字，trim 后空串视为不筛选；SQL 使用绑定参数，LIKE 特殊字符按普通文字搜索时要转义。排序只接受服务端白名单，例如后台 updatedAtDesc；禁止接受任意 SQL 列名/排序表达式。日期筛选使用明确起止边界，后台“到某日”转换成该日后一天零时的开区间。

9.3 会话与 CSRF 联调顺序

1. 后台打开后 GET /api/admin/auth/csrf，允许匿名访问，返回当前 csrf token，Cookie 由浏览器保存；响应 no-store。

2. POST login 使用表单编码 username/password，请求头 X-CSRF-TOKEN 携带 token；使用 Spring Security 的认证过滤器与 JSON 成功/失败处理，不自行拼 SecurityContext 代替完整认证流程。

3. 登录成功后重新获取 CSRF token，再 GET me；之后所有 POST/PUT/PATCH/DELETE 管理请求携带 token。退出后 token 和内存用户信息清理。

4. 管理请求收到 401 导向登录页并提示会话过期；403 显示权限不足，不重复登录、不自动重放发布请求。

5. 开发使用 Vite proxy 将 /api 转发到 Java；生产使用 Nginx 同源代理，避免不必要跨域。

Spring Security 默认对不安全 HTTP 方法提供 CSRF 保护，SPA 需正确传 token，见官方 CSRF 说明。公开只读接口不需要登录；POST leads 可作为唯一明确排除 CSRF 的公开业务写入口，同时执行限流、字段及 Origin 检查；Origin 检查不替代防机器人机制。不要为解决联调问题全局关闭 CSRF。

返回新的状态、lockVersion、处理人显示名与处理时间。对这条处理记录的更新也要乐观锁，避免两名管理员相互覆盖。

11.2 状态、路由与错误

• 页面区分 loading、success-empty、success-data、error，不能把请求失败转为空数组后显示“暂无内容”。

• 首页可选区块 null 或无有效条目则不渲染整块；列表为空保留标题/筛选，显示“暂无相关内容”和清空筛选入口。

• 详情 API 404 展示 404 页；网络错误/500 保留重试，不能误判为内容不存在。

• 列表筛选放在地址栏 query，浏览器前进/后退恢复；快速切换筛选时取消旧请求或使用序号防止旧结果覆盖新结果。

• 首版不在 localStorage 缓存 CMS 数据；站点配置与首页是独立请求，一个失败时另一个仍可呈现并提供重试。

• 顶部提供少量静态兜底，如中性的“公司官网”和返回首页入口；不能在请求前闪现参考公司的名称或测试素材。

• API 客户端合理超时，例如 10 秒；读请求可由用户重试，写请求不得自动无条件重放。咨询仅按同一幂等 key 允许用户重试。

11.3 响应式和交互

至少验收 375、768、1440 像素宽度。页面整体不得横向滚动；导航在小屏收起，卡片按一列/两列/多列切换，长标题和长链接可换行。富文本图片最大宽度 100%，表格允许在自身容器横向滚动。

PC 图和手机图用 picture 等方式按断点切换；没有手机图回退 PC 图，object-fit:cover，预览必须检查裁切与文案可读性。封面固定比例、Logo contain，图像预留宽高避免布局跳动。首屏图优先加载，屏幕外普通图片可懒加载；失败显示中性占位和 alt。

菜单、轮播按钮、弹窗可通过键盘操作，焦点可见；弹窗打开后焦点进入，Escape 可关闭，关闭后回到触发按钮。表单字段有 label 和明确错误文案，不能只用颜色表示错误。不要把核心文字全部放入图片。

11.4 SEO 与渲染边界

路由切换更新 title、description；独立内容 SEO 优先，其次标题/摘要，再回退全站默认 SEO。图片 alt、页面一级标题、语义化链接属于首版要求。已发布页面可以生成 sitemap.xml，若纳入实现需从公开内容源生成，不能输出草稿；首版可以由部署文档维护基础 sitemap，不能宣称已自动化。

本基线使用 Vue SPA：浏览器刷新由 Nginx 回退 index.html，API 404 与前端 404 展示必须正确，但静态入口响应通常仍为 200。SPA 的 meta 更新不保证所有搜索引擎或社交分享抓取效果；若业务要求服务端完整 SEO HTML、HTTP 页面 404 或首屏抓取，则作为明确新增工作采用 Vue 的 SSR/预渲染方案并另验收。后台与预览应限制收录，但 robots/noindex 不能代替登录鉴权。

12.2 统一异常处理

使用全局异常处理，将参数错误定位到字段，将权限、引用、版本冲突转换为第 9 章状态。后端日志关联 requestId；官网和后台提示只显示可操作文案和 requestId，不显示 Java 堆栈、SQL、存储目录。上传被拒绝不能遗留半成品数据库行或可执行文件。

业务成功日志与内容写入在同一事务；失败审计在回滚后单独记录必要摘要，避免记录“发布成功”但内容未提交。静态文件不存在不要回退成 index.html；API 不存在要 JSON 404，不能返回 HTML 200。

12.3 性能和容量基线

首版按几百到几千条内容、30 个以内首页 Logo 设计。首页聚合批量读取关联，不出现一条卡片一次查询的 N+1；列表不查询大正文；图片不作为 base64 存数据库。请求体对 HOME/正文设置上限，例如 JSON 最大 1MB，上传单文件 5MB，代理与 Java 配置一致。

建议在约定测试机、500 条新闻和 20 并发公开读请求下验证 API P95 不高于 500ms（不含图片传输）；记录机器、数据量、工具、样本和结果后由带教确认是否适合作为项目门槛。此数值是目标，不代表本文已测得。图片压缩后再上传，首屏单张建议不超过 500KB；硬上限仍为 5MB。优先控制资源体积和查询次数，不为此引入分布式缓存。

4. 验证登录、公开首页、详情、图片、保存/发布与咨询；生产咨询测试需明确标记并由管理员处理。

5. 保存发布版本、时间、检查人、检查结果和恢复路径。若失败，根据迁移兼容性决定恢复旧应用或恢复完整备份，不能盲目覆盖数据库。

15.4 备份恢复

数据库与素材至少每日备份，上线前由公司明确保留天数、访问权限及恢复责任人。手机号加密密钥需要独立受控备份，否则数据库恢复后仍无法解密。首版建议暂定恢复点目标 24 小时、恢复时间目标 4 小时，再以实际恢复演练结果确认是否可达到。

必须在空测试库/目录做一次恢复演练，验证官网内容、图片、管理登录及咨询可读性，并记录时间与失败修正。恢复演练只使用测试数据，不把生产个人信息复制到不受控环境。备份文件存在不能代替恢复成功证据。

16. 运营人员常用操作示例

16.1 新增产品并展示到首页

编辑登录 → 产品管理新增 → 从素材库选图并填正文 → 保存 → 桌面/手机预览 → 管理员核对版本并发布 → 打开产品列表和详情验证 → 首页管理选择该已发布产品进入服务分组 → 保存并预览 HOME → 发布 HOME → 刷新首页验证点击与内容。仅发布产品不会自动成为首页推荐。

16.2 更换首屏及联系信息

上传新图片，不覆盖旧文件 → HOME 选新图、填文案与动作 → 保存草稿时官网保持旧图 → 检查手机裁切 → 发布 HOME → 刷新查看新图。电话在 CONTACT 修改、保存并发布；全站页脚和联系页自动使用新电话，HOME 无需重复录入。

16.3 首页推荐新闻与紧急下线

发布新闻 A/B → 首页选 SELECTED，顺序 B/A → 发布 HOME：首页按 B/A，新闻列表仍按展示日期。下线 A：详情 404，列表/首页移除 A；HOME 编辑页保留失效引用提示。要删除 A，先从所有相关草稿与发布配置中解除引用，再删除。

16.4 处理咨询

访客在产品详情提交 → 服务端确认成功 → 管理员咨询列表看到 NEW，详情核对来源和需求 → 记录处理说明改 CONTACTED → 完成后 CLOSED。无需通过任何公共接口查询手机号；编辑不能看到此流程中的客户资料。

16.5 误改后的处理

只保存的误改尚未影响官网，可依据当前发布快照重新编辑草稿并保存。已发布误改首版由管理员手动修正并再发布；没有完整历史版本回滚功能。必要时紧急下线内容并修正关联；系统故障则按部署备份恢复方案处理，不把数据库恢复当成日常内容撤销按钮。
