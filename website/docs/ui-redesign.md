# 官网视觉改版说明（对齐参考站）

目标：把官网从「浅色卡片站」改成参考站（G7 易流）那种**工业科技风**——深蓝导航与页脚、整幅大图首屏、去边框的大卡片、克制的蓝色强调色。仅改视觉层，不动数据模型与路由。

## 一、参考站的实际特征

从录屏抽帧（2560×1600，284 秒，71 帧）归纳出的六条规律：

1. **导航**：整条深蓝（近黑）通栏，白字，高度约 72px，右侧是高亮 CTA。
2. **首屏**：整幅照片/渲染图铺满，左侧压暗，白色大标题 48–60px，配描边按钮。
3. **内页页头**：同一套深蓝带，面包屑 + 大标题 + 一句话说明。
4. **内容区**：白底大字距，区块标题 32–40px，卡片无描边，靠图片与留白分层。
5. **指标区**：数字 40px 以上，细线分隔，不用卡片。
6. **页脚**：与导航同色，多列链接 + 联系方式 + 备案信息。

## 三、顺带修掉的三个真实缺陷

1. **首页首屏图与全站 Logo 公开访问 404**
   配置里的图片没有登记到 `cms_media_ref`，而 `/api/public/media/{id}` 只放行被「已发布内容或分类」引用的图片。
   修法：`SiteConfigService` 保存草稿时以 `source_kind='CONFIG'`、`source_id=cms_config.id` 登记引用，发布时整表复制；`MediaRepository.isPubliclyReferenced` 增加 CONFIG 分支。表结构的 CHECK 本就允许 `CONFIG`，无需迁移。

2. **详情页 404 时无限骨架屏**
   `load()` 没有 catch，接口 404 后 `loading` 永远为 true，页面既没有内容也没有「未找到」提示，还没有 h1。
   修法：区分 `404/400 → 内容不存在` 与 `其他 → 加载失败并可重试`，两种状态都带页头与 h1。

3. **深色区块里的标题不可见**
   全局 `h1..h4 { color: var(--c-text) }` 会覆盖继承色，咨询区标题因此变成深灰压在深蓝上。
   修法：`.cta__title` 显式白字；同时给 `.section--dark` / `.on-dark` 补白字规则。

## 四、验证结果

- **构建**：`web` 与 `server` 均 BUILD SUCCESS。
- **SEO/无障碍审计**（13 条路由）：h1 唯一、缺失 alt 图片 0、无名称链接 0、无标签表单控件 0、重复 id 0，全部通过。
- **横向溢出**：1440 与 390 两个视口 `scrollWidth` 均等于视口宽，溢出元素 0。
- **浏览器实测**：首页、产品列表/详情、案例列表、新闻列表、关于、联系逐页截图核对；移动端 390px 下单列、指标两列、Logo 两列、无截断。

审计口径修正一处：`alt=""` 是装饰性图片的正确写法，原脚本把它等同于「缺失 alt」。现改为忽略 `aria-hidden="true"` 容器内的图片，避免为了通过审计而给装饰图硬加描述。

## 五、必须说清楚的边界

- **图片是占位素材**：首屏背景、内容封面、客户 Logo 共 11 张，都是本次按参考站风格生成的抽象图/文字标，不是真实素材。上线前必须在后台上传真实照片与客户授权 Logo。
- **只改了官网，没改后台**：管理后台仍是原来的 Element Plus 风格，与参考视频无关。
- **没有做参考站的多级大菜单**：现在是点击展开的简单下拉，导航层级仍按文档 6.3 的两级结构。
- **首屏图片仍是 `<img>` 背景**：为兼容移动端单独一张图，没有改成 CSS `background-image`。
